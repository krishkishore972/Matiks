# Matiks — web recreation

A **web-only** recreation of the Matiks mental-math and puzzle arena, reverse
engineered from the shipped Android build `com.matiks.app` 1.51.0 (XAPK). It is a
working app, not a click-through: every board is generated by a real engine, every
attempt is timed and scored, and results persist in the browser.

There is no mobile app in this repository — the deliverable is the Next.js app in
`apps/web`.

## Quick start

```bash
pnpm install
pnpm --filter web dev      # http://localhost:3000
```

Other useful commands (all from the repository root):

| Command | What it does |
| --- | --- |
| `pnpm --filter web dev` | Dev server on port 3000 |
| `pnpm --filter web build` | Production build (type-checks as part of the build) |
| `pnpm --filter web test` | Engine, scoring and rule tests (Vitest) |
| `pnpm --filter web check-types` | `next typegen && tsc --noEmit` |
| `pnpm --filter web lint` | ESLint with `--max-warnings 0` |
| `pnpm test` / `pnpm build` / `pnpm lint` | The same, via Turborepo |

Requires Node 24+ (see `engines` in `package.json`) and pnpm 11.

## What is implemented

**Navigation and shell** — a centred 520px app column with a sticky top bar
(pies + streak) and a five-tab bottom nav (Arena, Puzzles, Compete, Quests,
More), matching the reference app's navigation model. See
[docs/reference/ui-inventory.md](docs/reference/ui-inventory.md).

**Daily Challenge** (`/daily`) — Sudoku, KenKen, Cross Math, Math Maze and
Hectoc, seeded from today's date so every player gets the same five boards.
Division bands, Snacc Skips and the minimum-score rule are all surfaced.

**Infinite Puzzle ladder** (`/puzzles`) — Queens, Tango, Zip, Pipes and Wend,
endlessly generated, with each puzzle's own rule set enforced.

**Duels** (`/compete`, `/play/[gameId]`) — Sprint, Fastest Finger, DMAS, Mind
Snap, Flash Anzan, Pin Ball Recall and Ability Duels (Sum of Squares), all
60-second formats except Flash Anzan's three rounds and Pin Ball's eight boards.
Each duel ends with a blitz shape derived from the lead across three 20-second
windows.

**Scoring, ratings and progression** — puzzle score from difficulty, accuracy and
speed; Elo-style per-mode ratings; XP, levels, an XP booster; quests and rewards;
streaks with purchasable shields; Pies economy and a Snacc store.

**Profile and statistics** (`/profile`, `/more`) — lifetime stats, accuracy,
median time, per-mode ratings and recent plays.

**Leaderboards** (`/leaderboard`) — global/friends/college scopes across the five
evidenced categories.

**States** — loading, empty, success and error states on every route, including
the "below minimum score" path that explains why a play did not count.

## Architecture

```
apps/web
├── lib/games/            pure seeded engines — no React, no DOM, no Math.random
├── lib/scoring.ts        minimum scores, scoring, quality bands, blitz shapes, rating, XP
├── lib/services/         the backend seam (storage → leaderboard/quests → Backend interface)
├── lib/state/player.tsx  React context over that seam
├── lib/hooks/            session stopwatch + accuracy ledger
├── components/games/     one component per board
├── components/GameHost   shared game chrome: how-to-play, timer, result sheet
└── app/                  routes
```

Two decisions shape everything:

1. **Determinism.** All board generation goes through `lib/rng.ts`
   (mulberry32 + FNV-1a string hash). `Math.random()` is never used for boards,
   so a daily puzzle is identical for everyone on a given date and reproducible
   in tests.
2. **A backend seam, not scattered mocks.** `Backend`
   (`lib/services/backend.ts`) is an interface with a `localStorage`
   implementation. Pointing the app at a real HTTP service means implementing
   that interface — no component changes.

Tests (`pnpm --filter web test`) cover the engines (uniqueness, solvability,
validation, rejection of illegal moves), the reflex question generators, Mind
Snap's tap scoring, Pin Ball's 1/0.5 rule, and the scoring/band/shape tables.

## Simulated data

There is no server in this build, and nothing pretends otherwise:

- Duel opponents are deterministic simulations. The ready screen says so, and
  the result sheet calls them a simulated rival.
- Leaderboard rows that are not the signed-in player are flagged `bot`, and the
  header explains that they are generated.
- Contests (80 in 8, Survival Saturday, Speed Run, Road to Kolkata) are listed as
  the interface the app exposes, marked **Needs server**, with an offline
  practice link instead of a fake bracket.

## Not included

Live multiplayer and matchmaking, contests, the Feed/Nets social surfaces, the
Patches and Flip Match ladder entries (their rules are not recoverable from the
artifact), and paid currency. Nothing above is faked in its place.
